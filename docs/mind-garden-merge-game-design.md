# 心象成长像素养成设计稿

版本：`v0.3`
状态：策划确认稿，尚未进入实现
产品：心象仪 / 成长页

## 0. 本版核心结论

这版策划把成长系统从“很多系统都想接一点”收束成一个更清楚的第一阶段。它不是独立游戏，而是心情记录的可视化收获层：

```text
写日记
  ↓
获得心种匣
  ↓
进入心象森林
  ↓
看今天的天气
  ↓
打开心种匣，放置植物
  ↓
三株同类同阶植物融合
  ↓
森林变大，金币收益增加
  ↓
用金币扩建、装饰，并为第二场景建房做准备
```

第一版的主角是 `心象森林`。
建房是第二场景，先完整策划，暂不抢第一版主循环。

当前定下来的方向：

- 导航显示名定为“成长”，比“花园”更能覆盖森林、建房和后续场景；场景内名称使用“心象森林”。
- 每日奖励使用“心种匣”，不直接把植物塞进棋盘。
- 植物主成长链改为：`苔藓 → 蕨类 → 灌木 → 乔木 → 古树`。
- MVP 只做 3 个植物家族：`晨露系 / 月影系 / 向阳系`。
- 心象分不直接决定奖励数量、赚钱速度或施工积分。
- Todo 只提供小幅辅助收益，不参与稀有度和基础奖励数量。
- 货币名称定为“金币”。
- MVP 不加入角色，只做植物、天气、金币、图谱和成就等基本成长功能。
- 成长页优先做沉浸式像素页面，只保留底部导航，不保留现有背景、顶部设置或同步按钮。

## 1. 产品定位

心象森林不是任务系统，也不是另一个统计面板，更不是要把心象仪变成游戏。它是日记和 Todo 习惯产生的可见成长层。

它应该让用户感觉：

- 我每天记录的东西，会在世界里留下痕迹。
- 情绪好坏都能产生内容，低落不会被惩罚。
- Todo 仍然服务现实任务，不被成长系统反向污染。
- 成长结果直接可见，不靠大量解释文案撑场面。
- 系统可以长期扩展，但第一版玩法必须简单、稳定、好懂。

心象森林的第一版只追求一个清楚的爽点：

```text
今天获得了什么 → 有没有能合成 → 森林是不是变大了
```

## 2. 成长页面外壳

### 2.1 沉浸式成长页

成长页面进入后，不再沿用普通 App 页面结构。

当前决策：

- 保留底部导航栏。
- 隐藏现有动态背景。
- 隐藏顶部设置按钮。
- 隐藏顶部同步按钮。
- 隐藏普通页面的标题、统计卡和系统说明。
- 成长场景占据主要视野。

桌面端也按沉浸式方向设计：进入成长页后，画面以成长场景为主，而不是左侧导航 + 普通内容页。底部导航作为跨页面入口继续保留。

如果后续桌面端发现“完全隐藏左侧导航”带来迷路感，再考虑加一个像素风的“工作台”入口，但第一版不在顶部放设置或同步按钮。

### 2.2 成长页 HUD

成长页内只显示必要信息。

```text
左上角：金币 / 心种匣 / 当前天气
右上角：成就入口
中央：像素森林场景
底部：现有底部导航栏
选中对象后：底部或侧边浮出对象信息
```

不常驻展示：

- 平均心象分
- 算法置信度
- 累计 Todo 数
- 大段规则解释
- 每日任务列表
- 长篇成就列表

成就入口可以在右上角，但成就详情不占主画面。

## 3. 美术与轻交互方向

### 3.1 像素风格

第一版采用 16-bit / RPGMaker 气质。

视觉原则：

- 地面、植物、建筑使用 tile + sprite。
- 色彩以森林绿、土黄、暖光为基础。
- 黄色用于可领取、可合成、新发现等重点反馈。
- 不做高饱和手游大厅感。
- 不把统计 UI 伪装成成长成果。
- 所有像素资源使用整数倍缩放，保持 `image-rendering: pixelated`。

### 3.2 场景镜头

推荐第一版使用固定俯视或 3/4 视角。

核心对象：

- 森林地块
- 植物
- 心种匣
- 金币收集反馈
- 天气粒子
- 成就入口

交互以点击、拖拽、合成为主。
移动端先保证触控舒服，桌面端再补齐键盘操作。

### 3.3 MVP 不加入角色

角色会增强 RPGMaker 感，但也会把产品重心推向“游戏”。MVP 不加入角色，先把记录成长的成果做好。

当前决策：

- 不做可操作角色。
- 不做守林人、小精灵或剧情 NPC。
- 不做角色行走、对话和事件。
- 后续如果成长系统稳定，再评估是否加入装饰性角色。

## 4. 数据输入边界

成长系统只读取已有生活数据，不反向污染生活数据。

| 输入 | 成长作用 | 边界 |
| --- | --- | --- |
| 日记打卡 | 发放心种匣 | 同一天只发一次 |
| 心象分 / 象限 | 天气、光照、植物概率倾向、表现风格 | 不决定奖励数量 |
| Todo 完成数 | 少量金币、整理行动力、未来施工加成 | 不决定稀有度 |
| 连续打卡 | 成就、场景解锁、装饰解锁 | 不做数值滚雪球 |

## 5. 每日核心循环

第一版每天打开成长页时的动作必须足够短。

推荐日常循环：

```text
进入成长页
  ↓
查看今日天气
  ↓
收取离线金币
  ↓
打开今日心种匣
  ↓
把新植物放进森林或仓库
  ↓
系统提示可融合项
  ↓
融合 / 整理 / 扩建
  ↓
离开
```

单次操作目标：30 秒到 2 分钟。

用户可以只领取和离开，也可以在有兴趣时整理森林。
成长页不能要求用户每天花很久维护，否则会变成负担。

## 6. 心种匣系统

### 6.1 为什么使用心种匣

每日奖励不直接生成植物，而是先进入心种匣。

原因：

- 有领取仪式感。
- 棋盘满时不会丢奖励。
- 可以暂存，用户不必每天整理森林。
- 后续可以做不同天气、节日、场景的心种匣。
- 更适合把“打卡奖励”和“摆放管理”拆开。

### 6.2 发放规则

基础规则：

- 每个自然日首次保存有效日记，获得 1 个心种匣。
- 同一天反复编辑日记，不重复发放。
- 日记删除后，不自动回收已经领取或融合的植物。
- 心种匣进入库存，不强制立即打开。
- 棋盘满时仍可获得心种匣。

幂等键：

```text
rewardKey = dateKey + entryId + rewardType
```

`rewardType` 第一版可以是 `daily_seed_box`。

### 6.3 打开心种匣

打开心种匣时，生成 1 株一级植物。

植物结果由以下因素决定：

- 当天日记的心象象限：调整家族概率。
- 当天心象分：影响颜色明度、天气适配和小变体。
- 当前场景：第一版只进入心象森林植物池。

不由以下因素决定：

- Todo 数量不决定植物稀有度。
- 心象分高低不决定植物价值。
- 连续打卡不直接让心种匣翻倍。

## 7. 心象与天气

### 7.1 心象分的边界

心象分只改变“世界如何表现”，不改变“用户值不值得奖励”。

心象分影响：

- 天气
- 光照
- 环境音
- 植物家族概率
- 植物颜色与小变体
- 场景动画
- 图谱故事

心象分不影响：

- 每日基础心种匣数量
- 植物基础产出
- 施工积分主数值
- 金币基础收益
- 成就是否可获得

这样可以保留心象仪的特色，又避免低心情被体验成惩罚。

### 7.2 天气来源

天气由前一天的心象状态决定。

这样当天进入森林时，会有“昨天留下了今天的天空”的感觉。

示例：

| 前一天状态 | 今日天气 | 视觉表现 |
| --- | --- | --- |
| 低能承压 | 雾 / 小雨 | 深绿、蓝灰、低云、潮湿地面 |
| 低能修复 | 晨露 / 阴晴 | 浅绿、水珠、柔光、慢粒子 |
| 高能紧绷 | 风 / 雷云边缘 | 云影较快、树叶晃动、风线 |
| 高能舒展 | 晴 / 金色光 | 暖光、明亮树冠、轻快闪点 |
| 平稳 | 多云 | 中性光照、轻微云影 |

天气只影响表现和概率倾向，不惩罚产出。

## 8. Todo 的成长作用

Todo 是现实任务工具，不是刷分入口。

第一版中 Todo 完成数只给小幅辅助收益。

推荐作用：

- 少量金币。
- 整理行动力。
- 未来建房的施工加成。

不推荐作用：

- 不决定心种匣数量。
- 不决定植物稀有度。
- 不决定高阶植物掉落。
- 不作为每日任务列表。

示例规则：

```text
当日完成 Todo 数 0：无额外加成
当日完成 Todo 数 1：+5 金币
当日完成 Todo 数 2：+10 金币
当日完成 Todo 数 3+：+15 金币，上限封顶
```

后续建房阶段可以改为：

```text
Todo 完成数 × 8 施工积分，上限 24
```

但第一场景里先不要让 Todo 影响植物稀有度。

## 9. 植物体系

### 9.1 MVP 家族

第一版只做 3 个家族，避免三合一太难凑。

| 家族 | 气质 | 心象倾向 | 视觉 |
| --- | --- | --- | --- |
| 晨露系 | 修复、柔和 | 低能修复 / 平稳 | 青绿、水珠、浅色叶片 |
| 月影系 | 安静、收纳 | 低能承压 | 蓝紫、夜光、圆叶或蕨叶 |
| 向阳系 | 明亮、舒展 | 高能舒展 | 金黄、宽叶、暖色光 |

后续可扩展：

- 风铃系：高能紧绷、风动、铃形花。
- 雷雨系：风暴、紫蓝闪光。
- 雪松系：冬季、冷色、常青。

### 9.2 成长链

主成长链采用：

```text
苔藓
  ↓ 三合一
蕨类
  ↓ 三合一
灌木
  ↓ 三合一
乔木
  ↓ 三合一
古树
```

原因：

- 比“藻类”更适合森林地表。
- 第一阶段也有可见生命感。
- 自然演替清楚。
- 像素美术容易做出层次。
- “古树”比“巨木”更有心象仪气质。

藻类可以留给后续湿地、湖泊或雨季场景。

### 9.3 阶段数值

第一版默认 5 阶。

| 阶段 | 名称 | 累计需要一级植物 | 金币产出 |
| --- | --- | ---: | ---: |
| 1 | 苔藓 | 1 | 1 / 小时 |
| 2 | 蕨类 | 3 | 4 / 小时 |
| 3 | 灌木 | 9 | 14 / 小时 |
| 4 | 乔木 | 27 | 45 / 小时 |
| 5 | 古树 | 81 | 140 / 小时 |

融合后的产出略高于三株原植物总和。
这样融合有价值，但不会无限指数膨胀。

### 9.4 什么叫“相同植物”

第一版融合条件：

```text
同一家族 + 同一阶段 = 可融合
```

例如：

```text
晨露系苔藓 × 3
  ↓
晨露系蕨类
```

暂不要求完全同品种，也不要求相邻。

原因：

- 家族只有 3 个，合成频率会比较舒服。
- 不要求同品种，可以避免卡格子。
- 不要求相邻，移动端更轻松。
- 后续如果想加策略性，可以单独做挑战花圃。

## 10. 合成与空间

### 10.1 合成规则

基础规则：

- 三株同一家族、同一阶段的植物可以融合。
- 融合消耗三株原植物。
- 生成一株同家族高一阶段植物。
- 新植物继承家族，获得新的唯一 ID。
- 合成结果进入图谱。
- 合成必须是事务，不能产生半成品。

### 10.2 空间规则

为了让三合一真正解决容量问题，第一版所有植物逻辑上都只占 1 格。

视觉可以变大：

- 乔木和古树可以溢出到周围格子上方。
- 溢出只影响显示，不阻塞周围格子。
- 点击区域仍以当前格子为主。

棋盘满时：

- 新心种匣继续进入库存。
- 已有心种匣不能强制打开到棋盘。
- 用户可以先融合、收纳或扩建，再打开。
- 不因为棋盘满而丢失每日奖励。

### 10.3 棋盘与仓库

MVP 建议：

- 棋盘使用 `6 × 6`。
- 初始开放 24 格。
- 其余格子用金币解锁。
- 仓库初始容量 12。
- 仓库植物不产出金币。

仓库用于减压，不应该成为收益最大化玩法。

## 11. 金币经济

### 11.1 货币定位

货币名称：`金币`。

金币只存在于成长系统，不反向影响日记、心象分或 Todo。

产出来源：

- 棋盘上已放置植物。
- 少量 Todo 完成奖励。
- 成就一次性奖励。

### 11.2 消耗口

第一版必须至少有几个明确消耗口，否则金币只是数字。

MVP 消耗：

| 消耗 | 作用 |
| --- | --- |
| 解锁森林空地 | 扩大棋盘容量 |
| 买小装饰 | 增强成果展示 |
| 仓库扩容 | 缓解棋盘压力 |

第二阶段消耗：

| 消耗 | 作用 |
| --- | --- |
| 建房材料 | 推进房屋阶段 |
| 建筑装饰 | 改变房屋外观 |
| 场景入口 | 解锁新区域 |

第一版商店可以很轻：一个木牌、树洞或小仓库入口即可，不需要复杂商城。

### 11.3 离线收益

离线收益基于已放置植物计算。

建议：

- 记录 `lastCollectedAt`。
- 打开成长页时结算离线收益。
- 离线收益上限 12 小时。
- 系统时间倒退不产生负收益。
- 收取时用像素粒子从植物飞向金币栏。

## 12. 图谱

图谱记录已经发现过的植物。

图谱结构：

```text
晨露系
  ├─ 苔藓
  ├─ 蕨类
  ├─ 灌木
  ├─ 乔木
  └─ 古树

月影系
  └─ ...

向阳系
  └─ ...
```

每个节点展示：

- 像素立绘
- 名称
- 家族
- 阶段
- 首次发现日期
- 当前持有数量
- 金币产出

不展示：

- 算法长说明
- 敏感日记正文摘要
- 复杂统计图

## 13. 成就系统

成就入口固定在右上角。

成就记录自然发生的里程碑，不做每日任务压力。

推荐成就：

- 第一枚心种匣
- 第一株苔藓
- 第一次融合
- 第一株蕨类
- 第一株灌木
- 第一株乔木
- 第一株古树
- 第一片森林
- 第一次收取金币
- 第一次扩建空地
- 解锁建房场景
- 完成地基
- 连续记录 7 / 14 / 30 天

不推荐成就：

- 今日完成 10 个 Todo。
- 连续 30 天心象分高于 80。
- 每天登录领取。
- 每周必须生成 AI 总结。

成就更像回忆相册，不是手游日常任务表。

## 14. 场景二：森林建房

建房是第二场景，不进入第一版 MVP。

### 14.1 解锁条件

建议解锁条件：

- 至少拥有 1 株乔木。
- 图谱发现数量达到 8。
- 累计收取金币达到某个门槛。

不建议用“连续打卡很久”作为唯一门槛，避免断签挫败。

### 14.2 一句话定义

用户利用森林产生的资源建造一座像素小屋。房屋从地基、一楼、二楼、屋顶到室内布置逐步完成。

### 14.3 建造阶段

```text
清理地面
  ↓
地基
  ↓
一楼
  ↓
二楼
  ↓
屋顶
  ↓
室内布置
```

示例数值：

| 阶段 | 需要施工积分 | 预期耗时 |
| --- | ---: | --- |
| 地基 | 1000 | 约 10-14 天 |
| 一楼 | 1600 | 约 16-24 天 |
| 二楼 | 2200 | 约 22-32 天 |
| 屋顶 | 1200 | 约 12-18 天 |

### 14.4 施工积分

心象分不直接改变施工积分。

推荐公式：

```text
基础施工 50
+ 日记打卡 25
+ Todo 完成加成，最多 25
= 当日施工积分，最多 100
```

心象只改变当天施工表现：

| 当日状态 | 施工表现 |
| --- | --- |
| 低能承压 | 整理木料、铺防潮层、慢动画 |
| 低能修复 | 打磨、清扫、补小草、柔光 |
| 高能紧绷 | 搬运、敲钉、风大、节奏快 |
| 高能舒展 | 阳光下高效搭建 |
| 平稳 | 稳定施工 |

这样低心情不会让房子盖得更慢，但画面会诚实反映当天状态。

## 15. 后续场景方向

心象森林和建房完成后，可以继续扩展场景。

候选：

- 湿地：使用藻类、芦苇、水面、雨季内容。
- 湖边：钓鱼、倒影、夜晚星光。
- 山坡：风、松树、石阶、小径。
- 室内：家具、收藏、图谱陈列。
- 工坊：道具、装饰、材料转化。

每个新场景都应遵循同一原则：

```text
生活数据提供输入
成长世界展示结果
不反向污染原始数据
不惩罚真实情绪
```

## 16. 技术架构原则

### 16.1 三层拆分

成长规则不要写死在 React 组件或渲染引擎里。

推荐结构：

```text
GrowthCore
  奖励、天气、融合、收益、建造、成就

GrowthStore
  SQLite 存植物、金币、图谱、库存、场景进度

GrowthRenderer
  第一版像素 2D，未来可替换 3D
```

### 16.2 引擎路线

策划阶段不安装引擎。

推荐路线：

| 阶段 | 技术 |
| --- | --- |
| 外壳原型 | React + CSS 像素布局 |
| 正式森林场景 | PixiJS |
| 未来 3D | Three.js / React Three Fiber 或 Babylon.js |

不建议第一版直接做 3D。
也不建议把正式融合、拖拽、天气粒子长期塞在 DOM 里。

### 16.3 数据安全

成长状态独立存储。

不能：

- 往真实 Todo 写测试内容。
- 删除用户日记或 Todo。
- 因成长系统回滚修改原始日记。
- 把成长存档和原始记录混在一张表里。

自动化测试必须使用临时库或隔离数据。

## 17. 第一版 MVP 范围

第一版做：

- 沉浸式成长页外壳。
- 像素森林画面。
- 金币 / 心种匣 / 天气 HUD。
- 每日日记生成心种匣。
- 打开心种匣生成一级植物。
- 3 个家族。
- 5 阶成长链。
- 三合一融合。
- 金币产出和离线收益。
- 棋盘和仓库。
- 基础图谱。
- 右上角成就入口。

第一版不做：

- 建房实装。
- 3D。
- 复杂商店。
- 稀有度系统。
- 跨家族培育。
- 好友、排行、分享。
- 每日任务。
- 付费、广告。
- Todo 刷分型奖励。

## 18. 验收标准

第一版完成时，至少满足：

1. 同一天编辑日记多次，只生成一个心种匣。
2. 棋盘满时，心种匣不丢失。
3. 三株不同家族或不同阶段植物不能融合。
4. 三株同家族同阶段植物融合后，只生成一株结果植物。
5. 融合失败不会产生半成品。
6. 高阶植物逻辑上仍只占 1 格。
7. 心象低分不会减少基础奖励数量。
8. Todo 不影响植物稀有度。
9. 关闭应用再打开，棋盘、库存、金币和图谱能恢复。
10. 成长页不显示普通 App 顶部设置和同步按钮。
11. 自动化测试不写入真实 Todo 或日记。

## 19. 仍需确认

这版已经收束了大方向，剩下的问题只保留少量真正会影响实现的决策：

1. 心种匣打开时是否需要一个确认动画，还是点击即开？
2. 初始棋盘开放 24 格是否合适？
3. 第一版是否先做纯前端推导存档，还是直接设计 SQLite 成长表？
